# Pastel Minibox: code review findings (2026-10-28)

A read-through of the DSP library, the seven devices, the engine, sequencer, live input, model/serializer, the plugin wrapper and the master-FX integration. The UI was only spot-checked for threading, and the borrowed EFX Grid effects (`Source/efx/dsp/**`) were not audited. Each finding gives the file and line, what goes wrong, and a suggested fix.

Severity: **High** = crash, corrupt audio, or a control that is plainly wrong. **Medium** = audible artefact or a broken feature in normal use. **Low** = edge case, doc drift, or performance.

## 2. Crashes and memory safety

### 2.1 Stack buffer overflow on large blocks (High)
- `Source/devices/fm/FmDevice.cpp` (render): `float mono[4096]; jassert (n <= 4096);`
- `Source/devices/sampler/SamplerDevice.cpp` (render): `float lfoBuf[4096];` with no check at all.

`Engine::prepare` takes `max(block, 16)` and the plugin and standalone both chunk at `maxBlock`, which is the host/device block size. Hosts doing offline bounces, and some audio interfaces, use 8192-sample blocks. `jassert` is compiled out in Release, so this is a silent stack overwrite. **Fix:** use the per-device `bufL/bufR` vectors (already `maxBlock` long), or cap `Engine::maxBlock` at 2048 and let the existing chunking loops split.

### 2.2 `Engine::process` truncates instead of chunking (Low)
`Engine.cpp`: `if (n > maxBlock) n = maxBlock;` silently renders only the first `maxBlock` samples (the rest stay zero). Both callers chunk today, but any new caller (the offline export, tests) would get gaps. Loop internally instead.

### 2.3 Data race on sample refs (Medium)
`SamplerDevice::zoneFor` (audio thread, inside `noteOn`) reads `refs[z]` (a `juce::String`) while `loadZone` / `load` assign it on the message thread. A non-atomic `String` copy/assign racing with a read can crash. **Fix:** keep a per-zone `std::atomic<bool> hasSample` for the audio thread, or decide zones from `zone[z].audio() != nullptr`.

### 2.4 NaN from project files (High)
`Serializer.cpp` `mixerFromJson` stores `level/pan/sendA/sendB` unclamped. `Engine::renderSub` computes `std::sqrt (0.5f * (1.0f - m.pan))`. With `pan > 1` that is NaN, and NaN then lives forever in the master FDN reverb, the tape delay feedback and the limiter. Also unclamped: master `volume`, `limitDb`, `delayFeedback`, `clickLevel`, `recordQuantize`. With `recordQuantize > 1`, the live-record micro-timing is inverted. **Fix:** clamp on load. Add a NaN guard (`std::isfinite`) at the master bus input as a last line of defence.

### 2.5 Lock values are neither validated nor snapped (Low)
`DeviceProcessor::setLock` stores the raw value, and file-loaded lock lanes are unclamped. `MonoDevice::render` indexes `shapeMap[lShape]` with `lShape = (int) pv (lfoShape)` and no clamp, so an out-of-range lock reads past the array. **Fix:** `locks[i] = layout[i].snap (value)` in `setLock`.

## 3. DSP logic issues

### 3.1 Shared drive state across L/R (High)
`dsp::Drive` holds one `OnePole tone` and one `DcBlock dc`. These callers run it on the left sample, then the right sample of the same frame:
- `PolyDevice::render`: `drive.process (l…); drive.process (r…)`
- `SamplerDevice::render`: `driveFx.process (l…); driveFx.process (rr…)`
- `DrumSamplerDevice::render`: `v.drive.process (l…); v.drive.process (r…)`
- `DrumsDevice::render`: `kitDrive.process (l, 1…); kitDrive.process (r, 1…)` (Tube, so the DC blocker is interleaved too)

As a result the tone low-pass and DC blocker see an interleaved L,R,L,R stream. That means L/R crosstalk, a cutoff that is effectively wrong, and in Tube mode a DC blocker that subtracts the other channel's sample. **Fix:** one `Drive` per channel (or a stereo `process (float& l, float& r)`).

### 3.2 Footage switch inverted (High)
`MonoDevice.cpp`: `rangeOct = ((int) pv (range) - 1) * -12.0f` and `PolyDevice.cpp`: `octave = ((int) pv (vaOctave) - 1) * -12.0f`. `Unit::Footage` formats index 0 as **16'** and 3 as **2'**, so 16' gives +12 semitones and 2' gives −24. It should be `(1 - index) * 12`, i.e. +12 per step toward 2'. Factory presets all use the default 8', so only user edits are affected.

### 3.3 Acid pedal: dry/wet misalignment (High)
`pedal::Board::process` returns the oversampled output (two 31-tap half-band FIRs: 15 + 15 samples at 2× = **15 samples at 1×**). `AcidDevice::render` then blends `out + (wet·restore − out)·dMix` against the undelayed dry signal. At any Mix between 0 and 1 this is a comb filter with its first notch near `fs/30` (1.6 kHz at 48 kHz). In addition:
- `Board::process` bypasses entirely when `amount <= 0.0005`. Sweeping the Drive macro up from 0 therefore jumps the signal by 15 samples, with stale oversampler and filter state (a click).
- The VCA "restore" envelope is applied to the delayed wet signal without the delay.

**Fix:** delay the dry signal by `latency` samples (a small ring buffer) before the blend. Keep the board running, or reset and crossfade, across the bypass threshold.

### 3.4 VA "Ring" mode isn't ring modulation (Medium)
`PolyDevice::renderChunk`: `stackOff[2] = {0, 0, -12}` puts oscillators 1 and 2 at the **same** pitch, and `sig *= s * 1.4f` multiplies them. The result is x², which doubles the octave and adds a DC offset. That DC then goes into the filter, and the VA engine has no HPF to remove it. The product is also taken after the sub was added to `sig`, so the sub gets ring-modulated too. **Fix:** give oscillator 2 an interval or ratio (or a separate "ring pitch" control), multiply only osc1 × osc2, and DC-block the result.

### 3.5 VA Drift does nothing on the DCO engine (Medium)
`wander = va ? … : 0.0f`. The DCO card shows a Drift knob (`EditorSpecs.cpp:70`). Either hide the knob on the DCO engine, or make it drive the documented "random tuning and cutoff offsets per voice" (ARCHITECTURE §8.1) for both engines.

### 3.6 Amp "Gate" mode clicks (Medium)
`MonoDevice::render` and `PolyDevice::renderChunk` (`ampSrc == 2`): while the gate is held the amp is a hard 1. At release it jumps to the envelope's current value (the sustain level, possibly 0). Note-on also steps from the previous level to 1 when the voice is still active (`fadeIn` only covers idle voices). **Fix:** run a separate ~1–2 ms gate slew and multiply by the release envelope only after gate-off.

### 3.7 Acid: no fallback to a still-held key (Medium)
`AcidDevice::handleEvent` NoteOff: when `held.count > 0` and the step is not a slide, nothing happens. `noteOn` stays true and the pitch stays on the released key. For example, hold A, play B, release B: B keeps droning until A is released. **Fix:** slide or retrigger to `held.top()` (last-note priority, as `HeldStack`'s comment describes).

### 3.8 FM issues (Medium)
- **Pitch EG start:** `RateLevelEnv::value` starts at 0, and for the pitch EG 0 means −12 st. The first note after load (and after `kill()`) swoops up from an octave below. Initialise the pitch EG at its L4 (0.5).
- **Voices that never free:** `RateLevelEnv::process` only goes idle in stage 3 when the target is `<= 1e-4`. Any operator with L4 > 0 (common in imported banks) keeps the voice "active" forever. That costs CPU, defeats `isSilent()`, and leaves stealing as the only way to free it. Carriers' L4 should end the voice, and modulators' L4 shouldn't keep it alive.
- **DX7 import** (`FmDevice::parseBank`):
  - Envelope levels `L1–L4 = l/99` are used as **linear amplitude**, but the DX7 levels are logarithmic (≈ 0.75 dB per step). Imported patches sustain far too loud and their decays are mis-shaped.
  - `KeyScale` reads `o[9]` (left depth) but the engine applies it above note 48 (the right side). It should read `o[10]`, or model both curves.
  - LFO PMS/AMS per operator are dropped, and `lfoAmp` is applied to the summed output.
  - Single-voice (VCED, 155 bytes) dumps aren't accepted.
- **Ops above Nyquist:** `SineOp::setFreq` clamps `inc` to 0.49, so a high ratio on a high note plays the wrong pitch instead of being muted.

### 3.9 Reverb card tail logic (Medium)
`DeviceReverb::process` keeps the plate running for 8 s after Mix reaches 0 "so the tail rings out", but `PlateReverb::process` scales its **output** by `mix`. The tail is therefore muted within the 20 ms Mix smoothing, and the 8 s of processing are spent on silence. To keep tails, apply Mix at the input (a send) and leave the return at unity, or drop the keep-alive.

### 3.10 Plate reverb RT60 calibration (Low)
`PlateReverb::set` computes `fbGain` with `0.0533 * size`, where `size = 0.6…1`, but the line lengths are scaled by `0.6 + 0.4 * size` (0.84…1). The mean of the eight lines is also 50.7 ms, not 53 ms. Decay times drift from the requested RT60, mostly at small sizes.

### 3.11 Stale buffers after bypass (Medium)
- `DeviceFx::process` skips `chorus.process` when the mix is ≤ 0.001 or the mode is 0, and skips `delay.process` when the mix is ≤ 0.001. The delay lines stop being written, so re-enabling replays whatever was frozen in them. For the tape delay that can be 2.5 s of old echoes, plus their feedback.
- `PolyDevice` and `AcidDevice` skip `delay.process` the same way.
- `DrumsDevice`: `resonator.process` only runs when `resMix > 0.001`.

**Fix:** keep writing the input (and decaying the feedback) while bypassed, or clear the buffers on re-enable.

### 3.12 Sampler-family playback (Medium)
- **Hard stops:** at the region end (`v.pos >= ePos`, `env.kill()`), and with Drum Sampler Length < 1, playback stops instantly. Unless the sample is at a zero crossing this clicks, and a Length cut almost always lands mid-waveform. Add a short (1–3 ms) end fade.
- **Retrigger click:** a Drum Sampler pad retrigger restarts `pos` with no crossfade, and `attackGain` starts at 0.25. Fast rolls and ratchets click. Drums already fades a "tail" copy, and the Drum Sampler should do the same.
- **No loop crossfade:** Sampler Loop mode has no crossfade, so loops click unless they are trimmed by hand.
- **Mono filter:** the Sampler's filter sums the voice to mono (`l = rr = mid`) whenever it is engaged (cutoff < 17.9 kHz, env or LFO amount ≠ 0). Stereo samples collapse.
- **Bit crusher on one channel:** in the Drum Sampler, `r = l * 0.5f + r * 0.5f` after crushing `l` only. The right channel is half un-crushed, and stereo pads become lopsided.
- **No anti-aliasing:** Hermite interpolation with no low-pass when pitching up, or when playing a 96 kHz file at 48 kHz, aliases. That is acceptable for the "Vintage" character, less so for "Clean".
- **Gate pads after Stop:** `AllNotesOff` doesn't release Drum Sampler pads in Gate mode, which never decay while "held". After Stop they play to the sample's end.
- **Rate-dependent choke:** `v.choke *= 0.995f` is per sample, so the choke fade time depends on the sample rate.
- **Dead code:** in `SamplerDevice::render` the line `rr = l * 0.5f + rr * 0.5f;` is immediately overwritten by `rr = l;`.

### 3.13 Oversampling quality (Low)
- `Oversampler2x` is a 31-tap Blackman-windowed half-band. Its transition band is wide, so it droops audibly in the top octave (≈ −6 dB at fs/2 of the base rate by design, and noticeable from ~14 kHz). It also lets through some aliasing just below Nyquist, especially at 44.1 kHz.
- `Drive` (Soft, Tube, **Fold**) runs at 1×. The wavefolder (`sin (x·g)` with g up to 15) aliases heavily, against ARCHITECTURE §6's "2× on drive".
- `SubOsc` (VA engine) flips on the sample of the main oscillator's wrap and only smooths with a 9 kHz one-pole. It isn't band-limited (the DCO's `Dco::sub()` is), so the sub-oscillator jitters and aliases on high notes.
- `Filters.h::oversampled()` (linear interpolation plus boxcar average) is unused. Delete it, because it is a poor anti-aliasing scheme if anyone reaches for it.

### 3.14 Expression and modulation rate (Low)
- `DeviceProcessor::expressionSemis` is evaluated once per `render` call, so pitch bend and the 5.5 Hz vibrato are stepped at block or sub-block rate (zipper on slow bends, a staircase vibrato at 512-sample blocks). Expression (CC11) gain is applied per sub-block in `Engine::renderSub` with no smoothing.
- `MonoDevice` declares and prepares `cutSm` but never uses it. Cutoff changes jump at block boundaries.
- Every `Lfo` (all devices, all voices) seeds its RNG with `12345u`, so S&H and noise LFOs produce identical sequences everywhere.
- Mono's Poly and Chord modes retrigger the shared LFO on every new voice (`if (! legato && v.slot.note < 0) lfo.retrigger()`), so chords stutter the LFO.

### 3.15 Voice handling (Low)
- `VoiceSlot` documents a "3 ms steal fade" (`stealCountdown`, `pendingNote`), but no device implements it. Stolen voices jump in pitch and level instantly, apart from the `velGain` glide.
- VA Unison releases all six voices when the *last pressed* key is released, even while other keys are held (no last-note fallback). The same goes for Sampler and FM in Mono mode when the newest key is released.
- `allocateVoice` takes an unused `clock` parameter.

### 3.16 Delay time ceiling (Low)
`TapeDelay` clamps to 2.4 s, so the "2 bar" and "1 bar" divisions silently clamp at slower tempos ("2 bar" at 120 BPM is 4 s). Either size the line for the longest division at 30 BPM, or remove those divisions from the delay menus.

### 3.17 Limiter colouration (Low)
`Limiter::softCeil` saturates everything above 0.9 × ceiling even when no gain reduction is needed, so loud mixes get mild distortion at all times. Apply the knee only to what the gain stage couldn't catch.

## 4. Sequencer and engine

### 4.1 Locks vs. early notes (Medium)
`Sequencer::scheduleStep` pushes `ClearLocks` and `Lock` at the step start `t0`, but notes with negative micro-timing or offset are emitted one step **earlier** (`emit (ns, …, true)`). Those notes play with the previous step's locks, and the locks are cleared again before the note's own step begins. **Fix:** schedule an early note's locks at the early note's time (or at the earliest note of the step).

### 4.2 Trigger-time parameters ignore locks (Medium)
The engine sorts Lock events before notes at the same offset, but several devices read `get()` (the stored value) at trigger time:
- `DrumsDevice::trigger` snapshots `get (partParam …)`, so pitch, decay, accent and choke as used by the model's `trigger()` ignore locks. `render()` re-snapshots with `pv()` afterwards, so a locked part mixes both values.
- `DrumSamplerDevice::trigger`: Start / Length / Reverse / Choke.
- `SamplerDevice::region()` (used by `noteOn` and `render`): Start / Length / Loop, and `noteOn`'s Reverse.
- `AcidDevice::trigger`: `accAmt`.

Locking sample Start per step is a core motion-sequencing feature, and today it doesn't work.

### 4.3 Locks end at the next step (Low/design)
Locks clear at every step boundary, so a locked note longer than one step reverts mid-note. Elektron-style locks hold for the trig's duration. Consider clearing a track's locks at its next *note*, not the next step.

### 4.4 Tail handoff holds only one pattern (Medium)
`Engine::process`: `tailPattern` is a single int. Switching A→B→C while A still rings overwrites it with B. A's devices are then neither rendered nor `Panic`ed, so their state is frozen mid-tail and resumes when A plays again. **Fix:** keep a small set of tailing patterns, or `Panic` the old tail pattern when it is replaced.

### 4.5 Time-signature change rewinds the pattern (Low)
`Sequencer::boundary` applies `pendingBeats` at *any* bar start and sets `step = 0`. A change made in bar 3 of 4 jumps back to bar 1.

### 4.6 Tempo and seek details (Low)
- Pending events (note-offs, ratchets, swung notes) are scheduled in absolute samples, so a tempo change mid-pattern doesn't rescale them.
- `seek()` doesn't move `beatPos`, so synced LFOs, delays and the device arp don't realign after a seek.
- If `pending` (capacity 8192) is full, `push()` silently drops events. A dropped note-off is a stuck note.

### 4.7 Sustain pedal per focused track (Medium)
`Engine::routeMidi` stores `sustainDown` and `sustained` under the **currently focused** track. Pedal down on track 1, switch to track 2, pedal up: track 1's `sustainDown` stays true, and every later note-off on track 1 is swallowed until the pedal is cycled again with track 1 selected. **Fix:** treat the pedal as global (or per MIDI channel), and on pedal-up release every sustained note on every track.

### 4.8 Live recording converts and drops data (Medium/design)
The first live-recorded note converts a step track to a piano-roll clip (`Track::convertToPianoRoll`). That conversion permanently drops per-step **probability**, **trig conditions** and the tie flag (`ClipNote` has no fields for them, and `n.flags & 3` on load drops tie). The user gets no warning and has no way back, apart from undo if it covers this.

### 4.9 Audio-thread locking (Low–Medium)
`Engine::process` takes `juce::ScopedLock` on `audioLock` (a blocking `CriticalSection`). The message thread holds the same lock while it:
- allocates (`copyPattern` copies a whole `Pattern` with vectors, `lockFor` creates lanes, `beginTake` reserves clips, `takeAuto` and `spans` grow),
- runs O(n·m) loops in `endTake` and `applyRecorded` (`std::find` inside `remove_if`),
- re-prepares every device in `Engine::prepare` (the look-ahead toggle in `MainComponent.cpp:434`).

Any of these can make the audio thread miss its deadline. ARCHITECTURE already lists a lock-free queue as "a later refinement"; until then, keep work under the lock to pointer swaps.

The UI also reads project data with no lock while the audio thread writes it. `PianoRoll::paint` iterates `tr.clip`, and `SeqView` does the same with steps, while `Engine::growAtEnd` (audio thread) appends clip notes and copies steps during a recording.

### 4.10 Learned CCs also reach the engine (Low)
`MidiLearn::process` maps CCs to host parameters but doesn't remove them from the buffer. A CC1 / CC11 / CC64 learned to a macro still drives vibrato, expression or sustain in the device.

## 6. Performance notes (Low)

- **Per-sample transcendentals that could be per block:**
  - FM: `gainToDb`/`dbToGain` (log10 + pow) per operator per sample in `RateLevelEnv`, plus `semisToRatio (x.det)` per operator per sample.
  - Mono and VA: `std::exp` + `std::tan` (filter `set`) per voice per sample.
  - Drums: `std::exp (-1/(τ·sr))` recomputed every sample in most models (`DrumModels.h`).
  - Distortion pedal: `std::pow (66, tone)` per 2× sample.
  - Waveguide: `std::pow` per sample.
  - `Hpf4`: `std::exp` per 2× sample.
- `Oversampler2x::fir` uses `%` per tap; a doubled buffer or a mask would avoid it.
- The master bus runs the 8-line FDN reverb and the tape delay every sample even when every send is zero.
- VA voices keep rendering while only the *filter* envelope is still in release (`! aenv.active() && ! fenv.active()`), and this also keeps `isSilent()` false.

## 7. Hygiene

- `Source/app/presets/__pycache__/*.pyc` (6 files) are committed. Add `__pycache__/` to `.gitignore` and remove them from git.
- `CMakeLists.txt` prefers `../ersa/build/_deps/juce-src` when it exists. That is a JUCE checkout, so it isn't code borrowing, but it ties the build to a sibling project's build tree and to whatever JUCE tag that project has. Pin it with `FETCHCONTENT_SOURCE_DIR_JUCE` in a user preset instead.
- `DrumSamplerDevice::load` declares a `std::map cache` and never uses it.
- `presetName` defaults to `"Init"`, although the product rule is "no Init preset". It only shows if a device is created without `presets::loadDefault`.
- Duplicated comment lines in `Engine.h` (`growAtEnd` block and `recordTake`).

## 8. Build and tests

`cmake --build build --target MiniboxTests` is up to date and builds cleanly. `MiniboxTests` (the plain run, no tools): **92 tests, 2864 checks, 1 failure**, the same on two runs:

```
FAIL [perf_full_rack_cpu] full rack under 15 % of one core: 29.2 %   (second run: 15.6 %)
```

The full rack is over its CPU budget and the figure is noisy. §6 lists the obvious per-sample costs.

Test gaps that match the bugs above (none of these would be caught today):
- No test renders a stereo source through Drive (would catch §3.1) or sweeps the footage switch (§3.2).
- No test measures Acid's Drive Mix at 50 % for a comb (§3.3), checks that a p-lock on Drum Sampler Start moves the start (§4.2), or renders with a block > 4096 (§2.1).
- `dsp_ladder_self_oscillation` tests `dsp::Ladder4`, which no device uses.
